# v0.1.7

## Windows QR Login Fix

This patch addresses [Issue #1](https://github.com/YYYYYangjijjia/codex-wechat-plugin/issues/1).

The Windows login command previously passed the QR URL to `cmd /c start` without protecting it from shell interpretation. For a link ending in `?qrcode=...&bot_type=3`, `cmd` interpreted the ampersand as a command separator and opened a URL missing `bot_type=3`. The resulting QR code could display a network error in WeChat even though the CLI printed the complete original URL.

The browser launcher now passes the URL through a child-process environment variable to a fixed PowerShell `Start-Process` command. Query parameters remain intact and URL content is not interpolated into command text. If the launcher executable cannot start, the CLI points the user to the printed link.

The default `bot_type=3`, QR login endpoints, and login polling behavior are unchanged. This patch does not add the newer upstream verification-code login flow or QR API response validation.

## Validation

- All 198 tests passed; TypeScript type checking, build, and plugin manifest validation passed.
- Reproduced the phone-side network error with the old automatic opener on Windows / Node.js 22.20.0. Opening a complete fresh QR URL manually allowed binding, returned `connected: true / confirmed`, and delivered an inbound test message.
- Added regression tests that run the launcher command in real Windows PowerShell with the production process options and capture the argument passed to `Start-Process`, without opening a browser. Coverage includes command execution, ampersands, percent signs, quotes, shell expressions, and Unicode.
- Tested the fixed opener with the actual default browser and a temporary loopback HTTP endpoint to verify that the full query string reaches the browser.

The original reporter's Node.js 24.15.0 environment has not been retested. The successful real WeChat binding above used the complete-link workaround before this patch; the fixed opener was subsequently verified with the Windows subprocess and browser checks.

## Upgrade

From your repository checkout:

```powershell
git pull --ff-only
npm ci
npm run build
npm run login
```

If you also use the installed Codex plugin, run `npm run install:plugin` from the updated checkout and restart Codex Desktop.

To open a login link manually when troubleshooting:

```powershell
npm run login -- --no-open
```

Copy the entire printed `qrcode_url`, including `&bot_type=3`, into the browser and scan the newly displayed QR code.
